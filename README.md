# /btw 侧信道问答

> 在对话里临时问一句，看得到完整上下文，却不落进会话记录。回答落在侧栏小窗，随时回看。

`btw` 是 Hana 的一个轻量插件，等价于 Claude Code 的 `/btw`。名字取自 *by the way*：主话题之外，顺手问一句。

---

## 它解决什么

对话推进到一半，你常有这种念头冒出来：

- 我们刚才到底定了哪个命名？
- 之前提的那个概念，展开讲讲
- 这个语法细节我记不清了

这些念头若直接发进对话，会打断主线，也在会话记录里留下一堆岔路。`/btw` 给它们开一条旁路：它能读到当前会话已经发生的一切，回答却只给你看，主对话完全无感知。

## 三个性质

| 性质 | 说明 |
| --- | --- |
| 上下文可见 | 提问时携带当前会话历史，回答贴合你正在聊的内容 |
| 无工具 | 回答只来自已有上下文，不读文件、不跑命令、不联网 |
| 临时不落盘 | 问题与回答都不写入会话记录，主对话无感知 |

正因为「不落盘」，它天然不适合需要读取未读文件、或需要联网检索的问题：上下文里没有的东西，它答不了。

## 用法

```
/btw <问题>
```

例如：

```
/btw 我们刚才决定用哪个动画压缩格式？
```

回答以一条临时提示的形式出现在对话里（约 3 秒后自动消失），同时写进侧栏的「/btw 问答记录」小窗，常驻可回看。

## 侧栏小窗

插件在 Hana 侧栏提供一个常驻 widget：

- **实时状态**：空闲时一颗绿点；生成中显示 spinner 加正在提问的内容
- **即时刷新**：后端用 SSE 推送变更，新问答落盘后小窗立即出现，无需手动刷新
- **折叠展开**：问答默认收成一行，点击展开全文；新到的那条自动展开
- **Markdown 渲染**：回答支持标题、列表、引用、行内代码与围栏代码、链接，渲染前转义防注入
- **复制**：一键复制为一对 `Q:` / `A:` 文本
- **单条删除**：两段确认，防误触
- **清空全部**：同样两段确认
- **来源会话**：每条记录附带提问所在会话的标题，便于回溯
- **主题跟随**：消费 Hana 主题 CSS 变量，明暗与配色和界面一致

## 数据存储

数据统一放在正式插件数据目录，handler 与 widget 路由读写同一份文件，dev 与正式插件共用路径：

```
<HANA_HOME>/plugin-data/btw/
├── history.json   # 问答记录（最多保留 20 条，同题去重，新的在前）
└── status.json    # 生成状态标记，生成完成或失败后清除
```

`HANA_HOME` 默认是 `~/.hanako`。

## 权限与隐私

manifest 声明两项能力：

- `model.sample`：调用模型完成回答。请求不携带 `sessionId`，因此不会写回会话记录
- `session.read`：读取当前会话历史，作为提问的上下文

会话历史在拼进 prompt 时经过截断（最近 50 条、上限 12000 字符，超出取尾部），`trust` 为 `full-access`。所有内容只在本机与所配置的模型端点之间流转。

## 安装

把插件目录放到 Hana 的插件目录下：

```
<HANA_HOME>/plugins/btw
```

然后在 Hana 中重载插件即可。开发时可借助插件 dev 槽加载源码目录调试。

## 目录结构

```
btw/
├── manifest.json          # 插件清单：id、能力、widget 贡献点
├── commands/
│   └── btw.js             # /btw 斜杠命令：读上下文 → 采样模型 → 落盘历史 → 临时回复
├── routes/
│   └── ui.js              # widget 页面与 API（history / status / SSE stream / DELETE）
├── assets/
│   └── widget.js          # 小窗前端：渲染、交互、SSE 重连、兜底轮询
└── skills/
    └── btw/
        └── SKILL.md       # 供 Agent 识别 /btw 场景的技能说明
```

## 已知边界

- 仅基于会话上下文回答，无法读取上下文之外的文件或信息，也不会联网
- 网络/文件类问题答不了，属于设计取舍而非缺陷
- 历史最多保留 20 条，超出按新进旧出淘汰
